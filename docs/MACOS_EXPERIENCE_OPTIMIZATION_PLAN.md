# 我的日常 · macOS 原生体验优化方案

日期：2026-10-06  
文档版本：1.0  
状态：待确认的设计与实施方案，尚未进入开发

## 1. 背景与目标

当前应用已完成第一版功能、本地持久化与备份恢复，并经过两轮视觉和交互优化。已有统一配色、玻璃侧栏、图标操作、笔记整框点击及未完成事项详情访问。上一轮全量验证包含 45 项核心／模型测试和 14 项界面测试。

下一轮目标是改善页面结构与操作连贯性，使应用更适合长期在 Mac 上使用：

- 高频操作位置稳定，减少查找按钮和反复打开弹窗。
- 笔记、任务、训练等页面按各自场景组织内容。
- 鼠标与键盘都能完成主要操作，焦点和选中状态清楚。
- 重新打开应用后能够继续上次的工作。
- 保留现有本地数据、离线能力、提醒及备份恢复功能。

## 2. Skill 的使用方式

参考开源 [macos-app-design / SKILL.md](https://github.com/heyimjames/ios-design-skills/blob/main/plugins/heyimjames/skills/macos-app-design/SKILL.md)，采用其中窗口、导航、工具栏、键盘与列表交互的审查思路。

该 Skill 是社区设计指南，不是苹果官方规范。本方案中的尺寸是针对当前应用提出的初始设计值，应通过实际布局验证；其示例代码和 API 也需核对项目的 SDK 与最低系统版本。当前仅参考其内容制定方案，未安装 Skill 或据此修改应用代码。

实施时用 Skill 检查实际代码、提出具体改动，再通过截图与操作测试验收。产品范围仍以本方案和用户确认结果为准，不自动加入 Skill 涵盖的全部功能。

## 3. 优化清单

| 当前情况 | 建议调整 | 用户可感知的变化 |
| --- | --- | --- |
| 整体布局：各模块共用大标题、副标题和外层滚动区域 | 首页保留总览布局；笔记、开发采用列表与详情布局；今日计划采用任务列表布局。功能页标题由当前 28pt 试调至 22pt，减少顶部占用 | 不同模块符合各自场景，小窗口显示更多有效内容 |
| 导航栏：固定宽度，不能折叠 | 保留统一文字起点和模块色；支持折叠，展开宽度建议为 180–260pt，默认 200pt | 阅读和编辑时可以给正文更多空间 |
| 工具栏：主要操作分散在页面内容中 | 建立固定顶部工具栏，放置标题、适用的日期控制、搜索和新增入口；单条记录的操作继续贴近该记录 | 滚动后仍能找到主要操作，各页操作位置一致 |
| 笔记：列表固定宽度 235pt，与正文处于同一外层页面结构 | 列表宽度可在 220–320pt 调整；列表与正文独立滚动，搜索固定在列表顶部；恢复上次选中笔记 | 长文阅读与切换笔记互不干扰 |
| 今日计划：点击事项打开弹出编辑窗口 | 宽窗口支持右侧约 320pt 的详情区，小窗口继续使用弹窗；保留整行查看和独立完成、删除按钮 | 连续查看任务时减少重复开关弹窗 |
| 开发工作：项目内容以多个区域展示 | 左侧选择项目，右侧切换任务、问题、笔记、进展；区分项目级与记录级操作 | 内容增加后仍容易定位 |
| 健身：训练组以表单形式排列 | 对齐组数、次数、重量、完成列；明确单位；支持 Tab 连续填写，新增组后聚焦首个输入项 | 连续录入更快，减少鼠标往返 |
| 饮食与游戏：已有记录流程，历史浏览较基础 | 饮食保留计划与实际对照；游戏保留时长优先，并增加按名称筛选 | 记录清楚，查找历史更方便 |
| 图标交互：已完成图标化 | 统一悬停、键盘焦点及禁用状态；笔记、任务、项目补充右键菜单 | 简洁的同时提高可发现性与连续操作效率 |
| 菜单与快捷键：已有基础编辑菜单，业务入口不足 | 增加按模块执行的新建 ⌘N、适用页面搜索 ⌘F、设置 ⌘,；支持列表上下键选择 | 可用键盘完成常用操作，并能从菜单学习快捷键 |
| 窗口恢复：启动时创建固定大小窗口并居中，页面选择多为临时状态 | 记住窗口尺寸、位置、上次模块与选中记录；记录失效时进入合理空状态 | 重开后继续上次工作 |
| 设置：作为主窗口普通页面展示 | 增加独立设置窗口，分组展示通知、数据、备份；保留侧栏齿轮入口 | 设置不打断主页面，已有入口仍可找到 |
| 材质：玻璃导航、环境色与圆角卡片已建立 | 保留导航材质，减少内容区重复边框；正文与表格使用稳定底色，强调色表达选中与重点 | 层次更清楚，长时间阅读和填写更舒适 |

## 4. 关键交互约定

### 4.1 工具栏与快捷键

每个模块只展示适用操作。新建必须有明确对象：在笔记中新建笔记，在今日计划中新增待办；没有明确新建对象的页面不执行含糊的默认动作。按钮、菜单和快捷键调用同一操作，保持禁用条件一致。

正文输入时，方向键与删除键优先执行文本编辑，不得误触记录切换或删除。搜索快捷键只在具备搜索功能的页面生效。保留图标中文悬停提示及辅助功能名称。

文本撤销与记录删除撤销需要明确区分，不能直接用全局快捷键覆盖正在编辑的文本撤销行为。

### 4.2 笔记工作区

笔记列表、搜索和正文有各自稳定的区域。保留整框可点击、自动保存、标题与正文搜索、删除撤销。列表选中态与键盘焦点需区分。

切换笔记或模块前确保原有保存逻辑继续执行。恢复的笔记 ID 不存在时显示空状态或有效记录，不创建虚假记录。小窗口可折叠全局导航，不能让列表和正文互相覆盖。

### 4.3 今日计划详情

选择事项仅查看详情，不改变完成状态。详情区保持原有名称、说明、日期与提醒字段，以及保存和取消语义。用户编辑后切换记录时，要明确处理未提交修改，避免静默丢弃。

宽窄布局切换不清空正在编辑的内容。具体切换断点根据全局导航、任务列表与详情区的实际宽度确定，以现有最小窗口可用为底线。

### 4.4 窗口及页面恢复

窗口和界面偏好与业务记录分开保存。恢复前校验模块及记录是否仍有效；显示器断开时将窗口调整回可见区域。默认进入上次模块，但不得将上次查看的历史日期误显示成“今天”。

### 4.5 设置与材质

设置窗口复用当前数据与通知管理实例，避免重复写入或触发文件锁冲突。备份恢复保留格式校验、恢复前备份和用户确认，数据路径及失败提示继续可见。

保持现有 macOS 14/15 兼容材质和 macOS 26 原生 Liquid Glass 的版本区分；未经 macOS 26 实机测试，不宣称已验证该系统效果。尊重减少透明度、减少动态效果及深浅色设置。

## 5. 实施顺序

### 第一阶段：统一操作入口

- 优化功能页顶部空间，建立固定工具栏。
- 统一图标状态、菜单及快捷键。
- 保持现有模块内容结构，先验证操作一致性。

交付：可运行版本、各模块截图、快捷键说明和对应测试结果。

### 第二阶段：高频模块优化

- 优先完成笔记分栏、独立滚动与选择恢复。
- 再完成今日计划宽窗口详情区与窄窗口弹窗切换。
- 以上通过后，再调整开发工作、健身、饮食及游戏页面。

交付：各场景的关键操作录像或截图、布局与数据回归结果。

### 第三阶段：状态恢复与收尾

- 完成窗口及页面状态恢复。
- 增加独立设置窗口并保留原入口。
- 统一其他页面的间距、材质及小窗口表现。
- 全量测试、构建与版本说明完成后，再更新本机应用。

建议首批确认范围为：工具栏与快捷键、笔记工作区、窗口状态恢复。其余内容作为后续批次，避免一次改动过大。

## 6. 验收标准

实施前记录现有截图与测试基线。每项调整先明确对应测试，通过后继续下一项；最终运行全量测试，保留失败原因与修复记录，不删除、跳过测试或降低标准。

- **键盘操作：** 不用鼠标完成新建笔记、填写、搜索、列表切换；文本编辑不会误触记录删除。
- **任务查看：** 连续查看三条未完成事项，不误改变完成状态；说明与提醒编辑、取消及保存结果正确。
- **笔记滚动：** 长文滚动不带走列表搜索区域；列表滚动不改变正文位置；整框点击依旧有效。
- **数据保护：** 新增、编辑、删除撤销及重新启动后内容正确，备份恢复与主动提醒不回退。
- **状态恢复：** 正常退出重开后恢复窗口与有效选择；已删除记录、历史日期及显示器变化有合理回退。
- **布局：** 在现有最小窗口 880×620 及常规窗口检查遮挡、截断、滚动和操作可达性。
- **外观与辅助功能：** 浅色、深色、减少透明度、减少动态效果下保持清楚可用，图标有可读名称和焦点反馈。
- **交付：** 现有 59 项测试作为基线，新增对应测试；另执行离线、跨进程保存恢复、系统通知及仓库检查。

现有测试数量是上一轮结果，不代表本方案已实现或已通过测试。第一版待补的整机重启、休眠和通知点击人工验收仍独立保留。

## 7. 本轮范围边界

本轮不增加账号、云同步、手机端或运行时网络依赖，不更换本地数据格式。不将聊天助手、命令面板、多窗口编辑、菜单栏快捷记录、统计图表和自动更新同时纳入本轮。

开发沿用独立分支管理、保留原始数据与备份、更新前正常退出应用的交付流程。未经明确要求不合并主分支。
